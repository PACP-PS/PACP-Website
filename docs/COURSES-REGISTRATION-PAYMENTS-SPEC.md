# مواصفات وحدة الدورات والفعاليات والتسجيل الإلكتروني — PACP

## 1. إدارة كتالوج الأنشطة
أنواع الأنشطة القابلة للإدارة: دورة، ورشة، تدريب عملي، ندوة، مؤتمر، نشاط تطوير مهني، واجتماع علمي. الحقول: عنوان عربي وإنجليزي، وصف عربي وإنجليزي، أهداف ومخرجات تعلم، الفئة المستهدفة، المدربون، الجهة المنظمة، نمط التنفيذ، المكان/رابط المنصة، التاريخ والوقت والمنطقة الزمنية، الساعات، المقاعد، قائمة انتظار، رسوم النشاط وعملته، شروط التسجيل والإلغاء والاسترداد، حالة النشر، ومتطلبات الاعتماد والنقاط.

## 2. دورة حياة النشاط
مسودة ← مراجعة داخلية ← جاهز للنشر ← منشور ← التسجيل مفتوح ← التسجيل مغلق ← قيد التنفيذ ← مكتمل ← مؤرشف/ملغى. يجب حفظ هوية من غيّر الحالة والتوقيت وسبب الإلغاء. لا تنشر بيانات تجريبية أو أسماء/مواعيد افتراضية على الموقع العام.

## 3. دورة حياة طلب التسجيل
بدأ الطلب ← مُرسل ← قيد المراجعة (عند الحاجة) ← مقبول/قائمة انتظار/مرفوض ← بانتظار الدفع (إن كانت الرسوم مستحقة) ← مدفوع/إعفاء/مراجعة دفع ← مؤكد ← حضر/غاب ← استوفى متطلبات الإتمام/لم يستوفها ← شهادة مؤهلة/غير مؤهلة. ينبغي الفصل بين حالة الدفع وحالة التسجيل وحالة إتمام التدريب.

## 4. نموذج التسجيل
الاسم الرباعي بالعربية، الاسم القانوني الرباعي بالإنجليزية، البريد الإلكتروني، الهاتف، رقم العضوية الاختياري، النشاط، طريقة المشاركة، حالة العضوية، احتياجات التيسير الضرورية، الموافقة على إشعار الخصوصية. لا تجمع رقم الهوية أو تاريخ الميلاد في نموذج التسجيل للدورة إلا إذا كانت هناك ضرورة موثقة ومحددة.

## 5. الحضور والشهادات والنقاط
- تسجيل الحضور يدويًا أو برمز تحقق عند توافر بنية تشغيلية آمنة.
- توثيق متطلبات الإتمام والتقييم قبل فتح التسجيل.
- لا تصدر الشهادة إلا بعد تحقق شرط الإتمام الذي أُعلن للمشاركين.
- لا تمنح نقاط CPD إلا وفق سجل الاعتماد المعتمد والمُوثق.
- لكل شهادة رقم فريد، ومعرف نشاط وعضو، وتاريخ إصدار، وآلية تحقق عامة لا تكشف البيانات الشخصية.
- دعم إعادة الإصدار والإلغاء مع سجل تدقيق.

## 6. الدفع: مسار تحقق وتعاقد
لا يختار النظام مزودًا نهائيًا قبل التحقق من أهلية الجمعية التجارية والقانونية، بلد تسجيلها، إمكان فتح حساب تاجر، التسوية إلى حساب مصرفي متاح، الرسوم، العملات، الاسترداد، النزاعات، متطلبات التحقق من الهوية، دعم المدفوعات المحلية والدولية، وتوافق المزود مع Cloudflare/المعمارية المختارة.
- محلي: التحقق من التحويلات/وسائل الدفع المحلية المتاحة قانونيًا والتشغيليًا، وتحديد كيفية مطابقة الدفعات يدويًا أو آليًا.
- دولي: التحقق من قبول الكيان الفلسطيني والحساب المصرفي، البطاقات والعملات، رسوم التحويل والتسوية.
- لا تخزن المنصة بيانات البطاقة البنكية؛ استخدم صفحة دفع مستضافة لدى مزود متعاقد عند الموافقة.
- تحقق من إشعارات الدفع عبر توقيع webhook على الخادم، لا من صفحة عودة المتصفح وحدها.
- مفاتيح API في أسرار الخادم، لا في ملفات GitHub أو كود المتصفح.
- احتفظ بسجل مدفوعات، ومعرف عملية المزود، والمبلغ والعملة والحالة، دون تخزين بيانات البطاقة الحساسة.
- لا يُعلن أن الدفع متاح حتى اجتياز اختبار sandbox ثم اختبار تسوية حقيقي منخفض القيمة بموافقة الإدارة.

## 7. صلاحيات الإدارة
مدير البرنامج: إدارة الأنشطة. مسؤول التسجيل: الطلبات وقائمة الانتظار. مسؤول المالية: المطابقة والاسترداد والتقارير المالية. مسؤول الحضور: الحضور والإتمام. مفوض الاعتماد: توثيق النقاط وفق التفويض الرسمي. مدير النظام: الحسابات والإعدادات التقنية. يجب تطبيق أقل صلاحية لازمة وتسجيل الأحداث الحساسة.

## 8. الخصوصية والأمن
موافقة واضحة، تقليل البيانات، صلاحيات مبنية على الدور، تحقق خادمي من المدخلات، حماية من الطلبات المكررة، حدود للمحاولات، سجلات تدقيق، نسخ احتياطي، سياسة احتفاظ وحذف، وعدم إظهار بيانات المشاركين للعامة. لا تخزن بيانات صحية أو سريرية في هذه الوحدة.

## 9. تكاملات مطلوبة قبل الإطلاق
قاعدة بيانات وخادم API، مصادقة وصلاحيات، بريد إشعارات موثوق، تخزين خاص لوثائق الاعتماد، بوابة دفع بعد التعاقد، توليد PDF للشهادات، نظام تسجيل الحضور، سجل نقاط CPD، واختبارات وصولية وأمنية.

## 10. حالة التنفيذ
ملف HTML الحالي معاينة تفاعلية فقط؛ نموذج التسجيل لا يرسل أو يحفظ البيانات، والدفع والشهادات ولوحة الإدارة غير متصلة بخدمات خلفية. يجب ألا يُستخدم لجمع بيانات حقيقية قبل بناء وربط واختبار المكونات التشغيلية.
